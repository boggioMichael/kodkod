# פרויקט zit — git מבוזר לריפו ענק

צוותים של 3 מתכננים את zit: גרסה של git שבה הקבצים עצמם מפוזרים בין מחשבים, כך שאפשר לעבוד על ריפו של מיליוני קבצים ענקיים בלי clone מלא. כל צוות מוסיף פיצ'ר מיוחד שיהפוך את ה-zit שלו לטוב משל האחרים. מימוש בקוד הוא בונוס.

## הבעיה

`git clone` מוריד כל גרסה של כל קובץ. בריפו של משחק, סרט או מודל למידת מכונה זה מגיע לטרה-בייטים, והדיסק מתמלא לפני שמישהו כתב שורה.

- ב-git כל גרסה של קובץ היא blob שלם. סרט של 4GB ששונה עשר פעמים הוא עשרה blobs ענקיים.
- כל clone מחזיק את כל ההיסטוריה. מי שעובד על שלוש תיקיות מקבל את כל הריפו.
- הפתרונות הקיימים עדיין תלויים בשרת אחד. ב-Git LFS התוכן יושב בשרת LFS. ב-partial clone כל blob מגיע משרת אחד שאמור להחזיק את הכול, וההורדה נעשית אובייקט אחרי אובייקט ([תיעוד](https://git-scm.com/docs/partial-clone)).

הרעיון של zit: הקבצים עצמם מפוזרים בין המחשבים של הצוות. כל מחשב מחזיק את מה שקטן וחיוני, כמו commits ו-trees, ורק חלק מתוכן הקבצים. כשצריך קובץ, zit מוצא מי מחזיק אותו, מביא אותו, ומוודא שה-hash מתאים. זה עובד בזכות אותו רעיון משיעור 3: שם של אובייקט נגזר מהתוכן, ולכן לא משנה מאיזה מחשב מורידים אותו.

## איך עובדים

הפרויקט הוא גם מגרש האימונים של הקורס, ולכן התהליך ב-git חשוב בדיוק כמו התוכן.

1. **ריפו אחד לצוות**, בארגון של הקורס, מתוך תבנית הפרויקט.
2. **main מוגן מהיום הראשון**: PR עם אישור אחד, ובלי force push.
3. **כל שינוי ב-branch משלו**, בשם כמו `docs/protocol-draft` או `feat/where-command`.
4. **issue לכל משימה**, ו-`Closes #N` בתיאור ה-PR.
5. **קונפליקט נפתר ב-rebase על main**, והדחיפה עם `--force-with-lease`.
6. **הודעות commit לפי הקונבנציה שהצוות בחר** בשיעור 5, ונאכפות ב-hook.
7. **שיטת מיזוג אחת**, שרשומה ב-`CONTRIBUTING.md`.
8. **עד ההגשה, כל חבר כותב 5 PRs לפחות וסוקר 5**, עם הערות של ממש ולא רק Approve.

תבנית הפרויקט שאתה מכין מראש כוללת: `README.md` עם כותרות, `TEAM.md`, `CONTRIBUTING.md`, שלדים של כל קבצי `docs/`, `docs/decisions/0001-template.md`, ו-`.github/pull_request_template.md`.

## שאלות מנחות לתכנון

תכנון טוב עונה על כל השאלות האלה, ואומר במפורש מה הוא מקריב בכל החלטה. התחומים האלה הם בסיס טוב ל-issues שנפתחים בשיעור 3.

**אחסון**

- מה כל מחשב שומר תמיד, ומה רק לפעמים?
- מה יחידת הפיזור: קובץ שלם, או בלוקים של גודל קבוע? מה קורה לסרט של 50GB ששונתה בו דקה אחת?

**איתור**

- איך מחשב יודע מי מחזיק אובייקט מסוים: אינדקס מרכזי, טבלה מבוזרת, או שאלה לכולם?
- מה המחיר של כל בחירה, כשיש עשרה מחשבים? וכשיש אלף?

**checkout**

- מה קורה ב-`zit checkout` של commit עם מיליון קבצים? מורידים הכול, רק מה שנפתח, או משאירים מצביעים?
- איך מגבילים את המקום בדיסק? מה מוחקים ראשון, ומה אסור למחוק?

**push ושכפול**

- עשיתי commit לקובץ חדש של 10GB. לאן הוא הולך, ומתי ה-push נגמר?
- כמה עותקים של כל קובץ חייבים להיות, ומי דואג לזה כשמחשב עוזב את הצוות?

**אמינות ואבטחה**

- המחשב היחיד שמחזיק קובץ כבוי. מה המשתמש רואה?
- הרשת נפלה באמצע העברה של 20GB. מתחילים מההתחלה?
- מי רשאי לקרוא קובץ ששמור אצל חבר? מה מונע ממחשב לשלוח תוכן מזויף?

**תאימות**

- האם `git log` ו-GitHub עדיין עובדים על ריפו של zit? מה צריך להשתנות כדי שיעבדו?

## מקורות השראה

שום כלי קיים לא עושה בדיוק את zit, אבל כל אחד פתר חלק מהבעיה. כל חבר בצוות חוקר כלי אחד וכותב עליו ב-`docs/research.md`.

| כלי | הרעיון המרכזי | מה כדאי לקחת ממנו |
| --- | --- | --- |
| [git-annex](https://git-annex.branchable.com/) | תוכן הקבצים מחוץ ל-git. הכלי יודע איזה כונן או שרת מחזיק כל קובץ, מביא אותו ממי שיש, ועובד גם בלי רשת | מעקב אחרי "מי מחזיק מה" |
| [Git LFS](https://git-lfs.com/) | קובץ מצביע קטן נכנס ל-git, והתוכן עצמו בשרת LFS. הבחירה מה נכנס ל-LFS רשומה ב-`.gitattributes` | מצביעים במקום תוכן |
| [partial clone](https://git-scm.com/docs/partial-clone) | clone בלי blobs, וכל blob מגיע כשצריך מ-promisor remote | הורדה עצלה, והמגבלות של שרת אחד |
| [Scalar](https://git-scm.com/docs/scalar) | כלי של git לריפו ענק: מוריד רק commits ו-trees, מפעיל sparse-checkout ומריץ תחזוקה ברקע | איך git עצמו מתמודד עם ריפו ענק |
| [IPFS](https://docs.ipfs.tech/concepts/content-addressing/) | כתובת לפי תוכן (CID). קובץ גדול מחולק לבלוקים, בדרך כלל של 256KiB עד 1MiB | חלוקה לבלוקים, ואימות לפי hash |
| [filter ב-gitattributes](https://git-scm.com/docs/gitattributes) | `clean` רץ ב-`git add`, ו-`smudge` רץ ב-checkout | נקודת החיבור למימוש zit מעל git רגיל |
